# Установка 1С на сервере: Windows Server + MS SQL

Пошаговый разбор клиент-серверной установки 1С:Предприятие 8.3 на Windows Server 2022
с СУБД Microsoft SQL Server: подготовка ОС, установка и настройка MS SQL, установка платформы,
создание информационной базы, сервер лицензирования и базовая оптимизация кластера.

!!! note "Источник"
    Конспект статьи Академии Selectel «Как установить и настроить 1С на сервере»,
    сохранённой локально в MHTML. Скриншоты из оригинала убраны, шаги переписаны текстом.

## Клиент-серверная 1С

Платформа умеет работать в двух вариантах:

| Вариант | Как устроен | Когда использовать |
|---|---|---|
| **Файловый** | обработка и хранение данных на одном компьютере | тесты, персональное использование |
| **Клиент-серверный** | клиент + кластер серверов 1С + сервер БД | рабочие проекты |

В клиент-серверном варианте пользователь работает с клиентским приложением, запросы уходят
в кластер серверов 1С, тот обращается к СУБД, результат возвращается в клиент. Кластер и СУБД
можно разместить как на разных машинах, так и на одной.

Поддерживаемые сторонние СУБД: **Microsoft SQL Server**, PostgreSQL, IBM DB2, Oracle Database.
Чаще всего с 1С используют MS SQL — он и рассматривается ниже.

### Когда пора уходить с файлового режима

- Размер одной таблицы — не более **4 ГБ**: при приближении к лимиту база чаще зависает,
  при превышении таблица перестаёт открываться.
- Размер всей базы — рекомендуется не более **10 ГБ**.
- Одновременно работающих пользователей — не более **пяти**.

Если хотя бы одно условие нарушено, переходите на клиент-серверный вариант.

## Подготовка инфраструктуры

В примере используются два сервера с Windows Server 2022:

- сервер приложений — «1С:Предприятие 8.3»;
- сервер БД — Microsoft SQL Server.

### Подготовка ОС

**Включите сетевое обнаружение** на обоих серверах, чтобы они видели друг друга в локальной сети:

```
Параметры → Сеть и Интернет → Ethernet → Изменение расширенных параметров общего доступа
```

Проверка доступности: `ping <ip-адрес>`.

**Откройте порты в брандмауэре.**

| Порт | Протокол | Где открывать | Назначение |
|---|---|---|---|
| 1433 | TCP | сервер MS SQL | доступ к базам данных |
| 1434 | UDP | сервер MS SQL | SQL Server Browser |
| 1541 | TCP | сервер кластера 1С | рабочий процесс |
| 1560–1591 | TCP | сервер кластера 1С | диапазон динамических портов |

Порты 1541 и 1560–1591 нужны, только если пользователи подключаются с других устройств сети.

Правило создаётся так:

```
Брандмауэр Защитника Windows → Дополнительные параметры →
Правила для входящих подключений → Создать правило…
```

Далее: тип правила — «для порта»; протокол и порт — TCP/1433; действие — «разрешить подключения»;
профиль — доменный, частный и публичный; имя — например `MS SQL`.

**Установите Microsoft SQL Server Native Client**, если сервер 1С и сервер SQL — разные машины.
При установке на этапе «Выбор компонентов» включите «Клиентские компоненты».

### Установка MS SQL

1. Запустите скачанный установщик (например, `SQL2022-SSEI-Dev.exe`) и выберите вариант
   «Скачать носитель».
2. Смонтируйте ISO и запустите `setup.exe` → вкладка «Установка» → **«Новая установка
   изолированного экземпляра…»**.
3. Выберите вариант обновлений и нажмите «Далее».
4. На шаге «Правила установки» правило «Брандмауэр Windows» может быть в состоянии
   «Предупреждение» — установка пройдёт успешно, выключать брандмауэр не нужно.
5. Тип установки — «Выполнить новую установку SQL Server».
6. На шаге «Выпуск» выберите редакцию. Для разработки и некоммерческого использования
   подойдёт бесплатный **Developer**.
7. Примите условия лицензии, снимите галочку «Расширения Azure для SQL Server».
8. «Выбор компонентов» → **«Службы ядра СУБД»**.
9. Экземпляр — **«Экземпляр по умолчанию»**. Именованный выбирают, только если на сервере
   уже есть другие экземпляры.
10. «Конфигурация сервера»:
    - включить «Предоставить привилегию выполнения задач…»;
    - для «Агент SQL Server» и «Ядро СУБД SQL Server» тип запуска — **Авто**;
    - на вкладке «Параметры сортировки» — **`Cyrillic_General_CI_AS`**.
11. «Настройка ядра СУБД»:
    - выберите **смешанный режим** (SQL Server и Windows);
    - задайте пароль администратора `sa` — **он понадобится при создании информационной базы**;
    - добавьте пользователя-администратора SQL Server (удобно добавить текущего).
12. Вкладка «Каталоги данных»:
    - корневой каталог можно оставить по умолчанию;
    - каталоги пользовательской базы и её журналов лучше разнести на разные диски (если это HDD);
    - указывайте **существующие папки**, а не корень диска — иначе будет ошибка установки.
13. Вкладка «MaxDOP»: «Максимальная степень параллелизма» = **1** (рекомендация 1С).
14. Вкладка «Память» → «Рекомендуется» → принять рекомендуемые конфигурации.
15. Проверьте параметры и нажмите «Установить».

### Установка SSMS

`Microsoft SQL Server Management Studio` — необязательная, но удобная графическая консоль.
Ставится из «Центра установки SQL Server» → **«Установить средства управления SQL Server»**.

Подключение при первом запуске:

| Параметр | Значение |
|---|---|
| Тип сервера | Ядро СУБД |
| Имя сервера | имя вашего SQL-сервера |
| Проверка подлинности | Проверка подлинности Windows |

## Настройка MS SQL

### Сервер

**Включите TCP/IP**, иначе серверы не обменяются данными:

```
SQL Server Configuration Manager → Сетевая конфигурация →
Протоколы для <имя сервера> → TCP/IP → «Включено: Да»
```

Если 1С и MS SQL стоят на одной машине, вместо TCP/IP включают **Shared Memory**
(подробнее — в разделе «Оптимизация»).

**Включите смешанную аутентификацию** (`sa` должен иметь возможность входить по паролю):

1. Подключитесь в SSMS под учётной записью администратора (Windows-аутентификация).
2. Правый клик по серверу в «Обозревателе объектов» → «Свойства».
3. Вкладка «Безопасность» → «Серверная проверка подлинности: **Проверка подлинности SQL Server
   и Windows**».
4. Вкладка «Память» → «Максимальный размер памяти сервера» — максимально допустимое значение.

### Базы данных

В свойствах сервера, вкладка «Параметры базы данных»:

- включите **«Сжимать резервные копии»**;
- задайте пути по умолчанию для всех типов файлов БД.

Для созданной базы в «Свойства → Файлы» настройте **автоувеличение**: рост в мегабайтах,
максимальный размер — без ограничений. Если файлов несколько, разнесите их по разным дискам
(«Свойства базы данных → Файлы → Путь»).

Чтобы журнал транзакций не разрастался, поставьте **простую модель восстановления**:
«Свойства базы данных → Параметры → Модель восстановления».

### Регламентные задания

**Обновление статистик.** Оптимизатор строит план запроса по статистике распределения значений
в индексах и таблицах. Автообновления иногда не хватает — статистику стоит обновлять
не реже раза в сутки.

1. Создайте план обслуживания `Базовый`.
2. Добавьте вложенный план `Обновление статистик` с расписанием ежедневно в 23:00.
3. Добавьте задачу **Update Statistics Task**.

**Очистка процедурного кеша.** После обновления статистики старый неоптимальный план может
остаться в кеше и применяться дальше. Поэтому после обновления статистики кеш очищают:

1. Откройте вложенный план `Обновление статистики`.
2. Добавьте задачу **Execute T-SQL Statement Task**.
3. Соедините `Update Statistics Task` с новой задачей стрелкой (порядок выполнения).
4. В задаче укажите запрос:

```sql
DBCC FREEPROCCACHE;
```

5. Сохраните план.

## Установка платформы 1С

Запустите установщик 1С:Предприятие 8.3 и выберите «Выборочную установку».

| Компонент | Нужен |
|---|---|
| 1С:Предприятие 8 | обязательно |
| 1С:Предприятие — Тонкий клиент | необязательно |
| Тонкий клиент, файловый вариант | необязательно |
| Сервер 1С:Предприятие 8 | обязательно |
| Модули расширенного веб-сервиса | необязательно |
| Администрирование сервера 1С:Предприятия | обязательно |

Набор компонентов зависит от дистрибутива.

Далее:

1. Укажите путь установки и язык интерфейса.
2. На шаге «Установите сервер 1С:Предприятие 8 как сервис Windows» включите флаг
   и выберите **«Создать пользователя USR1CV8»**, задайте пароль.
3. Нажмите «Установить».
4. В окне драйвера защиты: если ключи аппаратные — «Установить драйвер аппаратных ключей защиты»;
   если программные — «Отключить неиспользуемые 1С:Предприятием возможности аппаратных ключей защиты».
5. По завершении перейдите в `..\1cv8\<версия>\bin` и запустите **`RegMSC.bat`** —
   он регистрирует утилиту администрирования серверов.

!!! warning "Ошибка при запуске службы «Агент сервера 1С»"
    Если при установке появилось предупреждение о невозможности запустить агент — запустите
    службу вручную в консоли управления службами и нажмите «Пропустить» в окне ошибки.

## Создание информационной базы

### Способ 1: из интерфейса 1С

1. Запустите «1С:Предприятие» → **«Добавить…»**.
2. Выберите «Создание новой информационной базы».
3. Выберите «Создание информационной базы без конфигурации…» (либо из шаблона, если
   куплена готовая конфигурация вроде 1С:Бухгалтерии — в шаблоне уже есть преднастроенная
   функциональность).
4. Тип расположения — **«На сервере 1С:Предприятия»** (это клиент-серверный режим;
   «На данном компьютере…» — файловый).
5. Заполните поля:

| Поле | Значение |
|---|---|
| Кластер серверов 1С:Предприятия | IP-адрес сервера 1С |
| Имя информационной базы в кластере | латиница, цифры только в конце, уникально в кластере |
| Защищённое соединение | «Установка соединения» |
| Тип СУБД | MS SQL Server |
| Сервер баз данных | IP или хост-имя сервера MS SQL |
| Имя базы данных | совпадает с именем ИБ в кластере |
| Пользователь базы данных | `sa` |
| Пароль пользователя | пароль `sa`, заданный при установке MS SQL |
| Смещение дат | 2000 |

Не забудьте флаг **«Создать базу данных в случае её отсутствия»**.

6. Параметры запуска: вариант аутентификации — «Выбирать автоматически», скорость соединения —
   «Обычная», основной режим запуска — «Выбирать автоматически».

### Способ 2: из MS SQL и оснастки администрирования

1. В SSMS: правый клик по «Базы данных» → **«Создать базу данных»**.
2. Укажите имя, владельца оставьте `<по умолчанию>` → «ОК».
3. На сервере кластера 1С откройте оснастку **«Администрирование серверов 1С Предприятия x86-64»**.
4. «Информационные базы» → правый клик → **«Создать → Информационная база»**.
5. Заполните: имя, защищённое соединение («Только соединение»), сервер баз данных (IP сервера
   MS SQL), тип СУБД (MS SQL Server), база данных (имя из шага 2), пользователь сервера БД `sa`,
   его пароль, смещение дат 2000 → «ОК».
6. Убедитесь, что база появилась в оснастке.
7. В «1С:Предприятие» → «Добавить» → **«Добавление в список существующей информационной базы»**.
8. Укажите наименование, на сервере 1С:Предприятия — IP кластера и имя базы.
9. Параметры запуска: аутентификация и режим — «Выбирать автоматически», версия 1С — 8.3.

## Сервер лицензирования (СЛК)

СЛК централизованно управляет лицензиями и работает как с программными, так и с аппаратными
ключами сразу для нескольких продуктов.

Плюсы:

- лицензии активируются не на каждом сервере, а в одном месте;
- при пересборке кластера не нужно активировать их повторно;
- изменение конфигурации сервера не требует новой лицензии — она привязана к серверу лицензий.

Установка:

1. Скачайте комплект «СЛК 3.0» с сайта разработчика (в оригинале — `3.0.34.11319`).
2. Из архива запустите `licenceserver-<версия>.win.exe`, оставьте параметры по умолчанию → «Установить».
3. Администрирование — веб-приложение: **http://localhost:9099**.
4. Вкладка «Установка лицензий»: 20-значный код, ИНН организации, место установки лицензии.

## Оптимизация и тонкая настройка

### Shared Memory

Режим использует оперативную память для обмена между кластером 1С и SQL Server, когда они
на одной машине, — это быстрее сетевого протокола.

```
SQL Server Configuration Manager → Сетевая конфигурация →
Протоколы для <имя сервера> → «Общая память» → включить
```

### Параметры кластера

Настраиваются в свойствах локального кластера в оснастке «Администрирование серверов
1С Предприятия x86-64» и действуют на все серверы кластера.

| Параметр | Что делает |
|---|---|
| **Интервал перезапуска** | через сколько перезапускаются рабочие процессы |
| **Допустимый объём памяти** и интервал его превышения | процесс, превысивший лимит за указанное время, принудительно перезапускается |
| **Принудительно завершать проблемные процессы** | платформа считает среднее число ошибок сервера к числу обращений за 5 минут; при флаге процесс с превышением завершается |
| **Выключенные процессы останавливать через** | сколько ждать завершения выключенного процесса: он не гаснет сразу, а остаётся включённым до окончания переноса данных либо до принудительного завершения |
| **Уровень отказоустойчивости** | сколько серверов может внезапно отключиться; от этого числа кластер считает объём ресурсов на синхронизацию |
| **Режим распределения нагрузки** | «Приоритет по производительности» — больше памяти, выше скорость; «Приоритет по памяти» — экономия ОЗУ |

### Параметры сервера 1С

Настраиваются для каждого сервера отдельно — это лимиты и резервирование памяти.

| Параметр | Значения |
|---|---|
| **Максимальный объём памяти рабочих процессов** | `0` — до 80 % ОЗУ сервера, `1` — без ограничений |
| **Безопасный расход памяти за один вызов** | `0` — 5 % от максимального объёма памяти рабочих процессов, `1` — без ограничения (не рекомендуется) |
| **Количество ИБ на процесс** | сколько информационных баз обслуживает один рабочий процесс |
| **Количество соединений на процесс** | лимит соединений на процесс |
| **Менеджер под каждый сервис** | запускать каждый сервис менеджера кластера отдельным процессом |

## Итог

Схема работ: подготовить ОС и порты → установить MS SQL с нужной сортировкой и смешанной
аутентификацией → настроить память, автоувеличение и регламентные задания → установить платформу
1С и зарегистрировать утилиты → создать информационную базу → при необходимости поднять СЛК →
выставить параметры кластера и сервера.
