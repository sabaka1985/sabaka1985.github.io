# Траблшутинг

Порядок действий при инцидентах: сначала локализовать, потом чинить.

## Страницы раздела

| Страница | О чём |
|---|---|
| [Диагностика сети](network.md) | ping, трассировка, DNS, порты, захват трафика |
| [Проблемы Windows](windows.md) | загрузка, домен, права, производительность |

## Общая методика

1. **Сформулировать симптом.** «Не работает» → что именно, у кого, с какого момента.
2. **Определить масштаб.** Один пользователь, отдел, весь офис, все площадки.
3. **Проверить, что менялось.** Обновление, новый GPO, переезд, смена провайдера.
4. **Разделить на слои.** Физика → канал → IP → порт → приложение → аутентификация.
5. **Проверить гипотезу одним действием.** Изменять по одной переменной за раз.
6. **Зафиксировать результат.** Что сделали и почему это помогло — в базу знаний.

## Матрица «симптом → где искать»

| Симптом | Первый подозреваемый |
|---|---|
| Нет сети вообще | кабель, порт коммутатора, VLAN |
| Пинг по IP идёт, по имени — нет | DNS |
| Пинг идёт, приложение не открывается | порт, файрвол, служба |
| Всё работает, но медленно | потери пакетов, MTU, диск, CPU |
| Только у одного пользователя | учётка, GPO, локальный профиль |
| Только с одного сегмента | маршрутизация, ACL, NAT |
| Работало, перестало после обновления | совместимость, конфиг |

!!! tip "Правило"
    Сначала соберите факты (логи, время, сообщения об ошибках), потом меняйте настройки.
    Одно изменение за раз — иначе непонятно, что помогло.
