# DNS и DHCP в Windows Server

## DNS: зоны и записи

| Тип записи | Назначение | Пример |
|---|---|---|
| **A** | имя → IPv4 | `fs01 → 192.168.10.20` |
| **AAAA** | имя → IPv6 | — |
| **CNAME** | псевдоним | `files → fs01` |
| **MX** | почтовый сервер | `mail.contoso.local` |
| **PTR** | IP → имя (обратная зона) | `20.10.168.192.in-addr.arpa` |
| **SRV** | служебные записи (AD, Kerberos) | `_ldap._tcp.dc._msdcs` |
| **TXT** | произвольный текст (SPF, проверки) | — |

- **Прямая зона** — имена в IP. **Обратная** — IP в имена, нужна для PTR и `nslookup`.
- **Условный форвардер** (Conditional Forwarder) — отправлять запросы по конкретному домену в другой DNS.
- **Forwarders** — куда уходят запросы, которые сервер не знает (`8.8.8.8`).
- **Scavenging** — автоматическая очистка устаревших динамических записей; включать вместе с aging.

Проверка:

```powershell
nslookup fs01
nslookup fs01.contoso.local 192.168.10.10
Resolve-DnsName fs01 -Server 192.168.10.10
ipconfig /flushdns           # сбросить кэш клиента
ipconfig /registerdns        # перерегистрировать запись клиента
Get-DnsServerZone            # список зон
Get-DnsServerResourceRecord -ZoneName contoso.local
```

## DHCP: области и параметры

- **Область (Scope)** — диапазон адресов для подсети.
- **Исключения** — адреса, которые не выдавать (под роутер, серверы, принтеры).
- **Резервирование (Reservation)** — закрепление адреса за MAC.
- **Опции области** — то, что сервер сообщает клиенту:

| Опция | Параметр |
|---|---|
| 003 | маршрутизатор (шлюз) |
| 006 | DNS-серверы |
| 015 | доменное имя |
| 042 | NTP-серверы |
| 066 / 067 | TFTP для PXE / файл загрузки |

**Резервное копирование** конфигурации DHCP (встроенная утилита):

```cmd
netsh dhcp server export C:\backup\dhcp.txt all
netsh dhcp server import C:\backup\dhcp.txt all
```

Срок аренды: 8 дней для офиса, 1–8 часов для гостевой сети с высокой ротацией устройств.

## Грабли

!!! warning "Типичное"
    - На DHCP-сервере стоит статический IP и он **не входит** в свою же область.
    - Две области пересекаются по адресам — конфликт адресов в сети.
    - DNS-сервер для клиентов указывает на роутер, а не на DC → `nltest` не находит домен.
    - IP-адрес сервера не исключён из области DHCP — адрес может достаться клиенту.
    - PTR-запись не создаётся: включите динамическое обновление DNS и age/scavenging.
